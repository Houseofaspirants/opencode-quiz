# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

House of Aspirants (houseofaspirants.in) — a static exam-prep site (Punjab Police / PSSSB quizzes, study material, current affairs). Plain HTML/CSS/vanilla JS, no framework, no bundler, no backend. Deployed on Vercel straight from the repo root (`vercel.json`, `cleanUrls`). Most HTML at the root and everything in `data/` is **generated and committed**; Python and Node build scripts produce it.

## Commands

```bash
bash scripts/ci.sh                         # the full gate (same as GitHub Actions): build everything, check, fail on drift
npm run publish                            # publish.sh: content scan → build_content → build_index → landing pages → ci.sh → git commit
npm run typecheck                          # tsc --noEmit over assets/js (jsconfig.json)
npm run content                            # node scripts/build_content_manifest.ts — scan PDF drops in content/**
npm run content:check                      # inventory in data/content-manifest.json == disk
python3 scripts/build_content.py [--strict]  # Markdown/PDF in content/ → pages, manifests, feed, search index
python3 scripts/build_index.py             # questions/ → data/index.json, data/quiz-manifest.json, sitemap.xml
node scripts/build-index.mjs               # Node twin of build_index.py (Vercel's buildCommand)
python3 scripts/build_landing_pages.py     # SEO landing pages (subject-/category-/topic-/quiz-/exam-*.html)
python3 scripts/seo_check.py               # SEO gate
python3 scripts/rich_results_check.py      # structured-data gate
python3 scripts/new_content.py --list      # scaffold a content draft (--type <t> --slug <s> [--pa])
npm run dev                                # build index + serve . (fetch() needs http, not file://)
npm run watch                              # auto-publish watcher (scripts/watch_service.sh runs it under launchd)
```

There is no unit-test suite; "tests" are the gates in `scripts/ci.sh`. Node ≥ 22.18 is required (runs `.ts` natively via type stripping); CI uses Node 24 and Python 3.12.

## Architecture

### Three source trees → generated site

| Source (hand-edited) | Builder | Output (generated, committed) |
|---|---|---|
| `questions/<subject>/[<category>/]<topic>.json` | `build_index.py` **and** `build-index.mjs` | `data/index.json`, `data/quiz-manifest.json`, `sitemap.xml` |
| `content/<collection>/*.md` / `*.pa.md` / `*.pdf` | `build_content_manifest.ts` then `build_content.py` | collection pages (`note-`, `ca-`, `magazine-`, `book-`, `material-`, …), hubs, `archive-*`, `author-*`, `pyq/<exam>/`, `current-affairs/<lang>/<month>/`, `feed.xml`, `data/search-index.json`, `data/content-manifest.json`, `data/content-graph.json` |
| `data/index.json` + `data/seo_copy.json` + config | `build_landing_pages.py` | `subject-*`, `category-*`, `topic-*`, `quiz-*`, `exam-*`, `cluster-*` pages, `data/landing-manifest.json`, `SEO-LANDING-REPORT.md` |

`build_content.py` imports helper modules from `scripts/` (`study_material`, `proof_documents`, `pyq_collection`, `current_affairs`, `content_engine`, and `books_engine` for `content/books/*.json` + `config/affiliate-links.json`). Each writes its own `data/*-manifest.json`.

**Never hand-edit generated output.** Change the source or the builder and rebuild. Pages carrying `generated by scripts/build_content.py - do not edit by hand` are overwritten. `build_content.py` also rewrites marker-delimited regions inside hand-written files: the `HOA-NAV` blocks in `assets/js/core.js` (navigation comes from the `HUB_NAV` table in `build_content.py`) and the `HOA-HOME:*` feed blocks in `index.html`. Don't remove those markers; the build fails if they are missing.

Hand-written pages are the app shells (`index.html`, `quiz.html`, `subject.html`, `result.html`, `mock.html`, `practice.html`, `study.html`, `pyq.html`, `books.html`, `leaderboard.html`, …) plus static/legal pages.

### Invariants enforced by `scripts/ci.sh`

1. **Twin builders must agree.** `build_index.py` and `build-index.mjs` must emit identical `data/index.json`, `data/quiz-manifest.json` (byte-for-byte) and `sitemap.xml`. Any change to quiz indexing logic must be made in **both** files.
2. **Filename derivation parity.** `build_content_manifest.ts` and `build_content.py` (`pdf_title_from_name` / `pdf_slug_from_name` / `pdf_date_from_name`) must derive the same title/slug/date from a PDF file name, including Gurmukhi names. Change both together; the fixtures live in `ci.sh`.
3. **Committed tree == builder output.** After rebuilding, `git diff` must be empty. Only the timestamps in `data/index.json`, `data/landing-manifest.json`, `SEO-LANDING-REPORT.md` and `sitemap.xml` are normalised. That `VOLATILE` table is duplicated in `publish.sh` and `scripts/ci.sh`; keep them in sync. So after any source or builder change, run the builders and commit their output along with it.

### Front end

- Every page has `<div data-site-header>` / `<div data-site-footer>`; `assets/js/core.js` injects the shared chrome, search, storage and offline handling, and exposes `window.HOA` (the API other page scripts call). Page-specific logic goes in `assets/js/<page>.js`.
- Pages read `data/*.json` with `fetch()` at runtime; topics are never hardcoded.
- Type safety without a build step: `// @ts-check` + JSDoc, with globals declared in `assets/js/hoa-types.d.ts`.
- `sw.js` is the offline service worker. **Bump `VERSION`** (`hoa-vNN`) when core assets change.
- Optional Firebase sign-in/cloud sync is configured in `data/site.json` → `auth`; the rules are in `firestore.rules`.

### Quiz data model

- A subject is flat unless `data/subjects.json` gives it a `categories` list, which adds a category folder level (GK uses this). Category folders that aren't in the config are auto-added.
- A topic file is an array of questions or an object with `questions`/`mcqs`/`quiz`. Each question has `q`, `options`, and `correct` (an index, a letter, or the exact option text), plus optional `explanation`, `reference`, `difficulty`, `topic`. Invalid files produce warnings and are skipped; they don't fail the build.
- **Multilingual:** one topic id, many language variants. A variant is detected from a language folder (`English/`, `Punjabi/`), a word suffix (`-punjabi`, `-english`, `-gurmukhi`; table `LANG_WORDS` in both builders), or a dotted ISO code (`topic.pa.json`). Variants must agree on question count, ids, option count and the correct index (saved answers are stored as indices). Front-end resolution goes through `pickVariantFile()`.

### Content (Markdown) rules

See `content/README.md` for the full front-matter contract. Key rules: `title` ≤ 60 chars and `description` 140–160 chars (both required); `author` must exist in `data/authors.json`; unknown keys warn, missing required keys fail; `draft: true` / `status: draft|archived` publish nowhere; raw HTML in Markdown is escaped. Nothing is written to disk unless every file validates. A PDF dropped into a collection folder publishes from its file name alone.

### Publishing flow

`publish.sh` builds, gates and commits as `publish content`. `scripts/watch_content.mjs` watches `content/` for PDF changes (3 s debounce, batched), runs publish, and pushes `main` over SSH.
